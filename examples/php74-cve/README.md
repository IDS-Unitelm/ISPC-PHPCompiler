# Experimental PHP 7.4 CVE mitigation build

This compiler can build the PHP source commit `712e60f9edfd03f0960fc4fc3c2c375f42b90aa2` from the upstream branch `PHP-7.4-CVE-2026-109618-109619`.

The pinned source identifies itself as **PHP 7.4.31-dev**, not PHP 7.4.33. The compiler downloads the archive generated by GitHub for that immutable commit and verifies its SHA-256 before extraction. No tarball needs to be stored in this repository.

## Important limitations

- This is an experimental backport for an end-of-life PHP line, not an official PHP release or a substitute for upgrading to a supported PHP version.
- The commit changes PHP core memory/error handling and multipart parsing. It disables the RFC1867 upload-progress callback, so features using `PHP_SESSION_UPLOAD_PROGRESS` may stop working.
- Run the PHP upstream test suite and application-specific tests before production use. The repository's regular release test matrix does not include this snapshot.
- The PHP source bootstrap requires `autoconf`, `bison`, and `re2c`; the compiler installs these with the selected distribution's package manager.

## Build and install

Run the compiler as root and select **PHP 7.4.31-dev CVE-2026 patched** from the menu:

```bash
sudo bash php-compiler.sh
```

The build installs side-by-side under `/opt/php74-cve`, creates the `/usr/bin/php74-cve` command and the `php74-cve-fpm` service, and does not automatically change the system `php` alternative.

## Verify

```bash
/opt/php74-cve/bin/php -v
/opt/php74-cve/bin/php -m
sudo systemctl status php74-cve-fpm
```

Run the repository smoke tests with the patched binary:

```bash
for test in tests/*.php; do /opt/php74-cve/bin/php "$test" || exit 1; done
```

Only switch the system CLI alternative after validation, if needed:

```bash
sudo update-alternatives --install /usr/bin/php php /opt/php74-cve/bin/php 74
sudo update-alternatives --config php
```

## Roll back

Stop and disable the service before removing the patched installation:

```bash
sudo systemctl stop php74-cve-fpm
sudo systemctl disable php74-cve-fpm
```

Then remove the `php74-cve` service files and `/opt/php74-cve` using the service-management procedure for the target distribution. If you manually added the CLI alternative, remove it with:

```bash
sudo update-alternatives --remove php /opt/php74-cve/bin/php
```
